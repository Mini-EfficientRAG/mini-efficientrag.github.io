Mini-EfficientRAG

Next-Query Extraction for Multi-hop Question Answering

A tiny reproduction of EfficientRAG that focuses on the next-query extraction stage: learning when to continue retrieving evidence and when to terminate and answer, using HotpotQA and open-source LLMs.

Project Overview View on GitHub

What is Mini-EfficientRAG?

Mini-EfficientRAG is a course project that replicates the core ideas of EfficientRAG on a smaller scale. It implements a retrieval-centric pipeline for multi-hop QA where an LLM iteratively issues <Continue> or <Terminate> next-queries, supported by a labeler–tagger and filter that decide which retrieved chunks are useful. The project runs on modest hardware (e.g., a single GPU in Colab) using FAISS-based retrieval and open-source LLMs.

System Architecture

Workflow of the next-query extraction and filtering pipeline used in Mini-EfficientRAG.

Retriever + FAISS Index

Dense passage retrieval over HotpotQA using pre-computed embeddings (e.g., Contriever / E5) and a FAISS index to provide candidate evidence chunks.

Labeler & Tagger

An LLM labels retrieved chunks as evidence and tags them as <Continue> or <Terminate>, producing supervision for the filter model and next-query generator.

Filter Model

A lightweight classifier trained on synthesized labels to keep or drop chunks, improving context quality while reducing total tokens fed into the LLM.

LLM Answer Head

An open-source LLM (served with vLLM) iteratively generates follow-up queries, consumes filtered chunks, and finally produces the answer to the multi-hop question.

Project Highlights

Key capabilities implemented in Mini-EfficientRAG

❓

Multi-hop Question Handling

Uses HotpotQA questions that require reasoning over multiple documents, mirroring EfficientRAG’s evaluation setting.

🔁

Next-Query Extraction

Self-ask style prompts drive the LLM to propose follow-up questions, which are then converted into retrieval queries.

🏷️

Labeling & Tagging of Chunks

The model labels retrieved chunks with supervision signals used to train the filter and to learn when to stop searching.

🧹

Evidence Filtering

A classifier keeps only high-value chunks, shrinking the context while maintaining answer quality.

📉

Token & Latency Analysis

Compares naive multi-hop RAG to EfficientRAG-style next-queries in terms of tokens retrieved and answer accuracy.

🧪

Reproducible Setup

Code structured for reproducibility on a single-GPU environment (e.g., Colab) using vLLM, FAISS, and HuggingFace models.

Experiments & Findings

Filter Model Performance

The trained filter achieves high F1 on predicting “useful” chunks, allowing the pipeline to discard noisy passages while keeping necessary evidence for correct answers.

Token Efficiency

Compared to a naive self-ask baseline that dumps all retrieved chunks into the context, our pipeline achieves similar or better accuracy with a noticeably smaller context window.

Takeaways for RAG Design

Even with small models and limited compute, structured next-query extraction and filtering provide tangible gains, making EfficientRAG-style ideas practical for research prototypes.
